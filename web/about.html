关于与引用

ForceBench 是一个基于 Isaac Lab 的仿真基准，用来测量 6 轴力/力矩反馈 究竟能不能、以及在多大程度上改善视觉-语言-动作（VLA）操作策略。

项目定位

每个任务在几何上原则上都能靠视觉和本体感受解决，但决定正确行为的那个物体属性 （重量、内部配重、机构阻力）在视觉上不可观测：策略要么必须用力信号才能超过随机水平， 要么根本不需要力 —— ForceBench 就是用来逐任务、逐策略地判断到底是哪一种。

八个任务，一套共享的机器人/控制器/观测契约，一个策略接口。换策略，不换测试台。

与 ForceVLA 论文的区别

ForceVLA（NeurIPS 2025）提出的是一个力融合 MoE 架构， 以及一套用于验证它的 5 任务真机数据集。

ForceBench 不是一篇竞争性的架构论文。它提供的是「方法无关」的对比所需要的那套测试台： 一个固定的仿真契约、一条分级的力信号阶梯（从纯本体感受，到原始 6 轴 wrench，再到架构级融合）， 以及一个共享的评测协议 —— 好让「力有帮助」成为一个可复现的基准结果， 而不是绑定在某一篇论文特定实验设置上的说法。

在这个框架里，ForceVLA 只是力信号阶梯上的一档（forcevla， force_input: moe_fusion），与 π0.5（none）、 π0.5+力6D（wrench6_concat）、ForceFlow 并列， 而不是被评价的对象或对照的靶子。完整名单以 results/leaderboard.json 的 models[] 为准， 见 Leaderboard 的提交记录表。

为什么坚持给置信区间

真机、乃至很多仿真操作论文报告成功率时的样本量都很小，一个孤立的百分数会严重高估结论的确定性。 ForceBench 的做法是：成功率永远和 Clopper-Pearson 精确二项 95% 置信区间一起出现， 不用正态近似（小样本、极端比例下正态近似会失真）。

原型状态与免责

⚠ v0.1 原型，请勿引用其中的数字

评测覆盖不完整，多个「任务 × 模型」组合从未跑过；成功判定本身仍在调整。 具体来说：目前只有 π0.5 与 ForceVLA 两个模型有有效结果，覆盖 8 个任务中的 6 个 （缺 gear_mesh 与 peg_insert）； π0.5+力6D 只有故障修复前的评测、已作废且尚未重跑； ForceFlow 的 checkpoint 存在但从未评测。 gear_mesh 任务当前还没有可用的专家数据。 数据与 checkpoint 的公开托管也尚未搭建。 在这些补齐之前，请把本站与本仓库中的任何成功率都视为临时数值。

这个网站本身

本站是纯静态页面（原生 HTML + CSS + 少量 vanilla JS），没有构建步骤、没有 npm 依赖、 不加载任何外部 CDN 资源，可直接由 GitHub Pages 托管。所有榜单数字在运行时从 results/leaderboard.json 读取，页面里不存在硬编码的评测结果； 读不到该文件时页面会明说「数据尚未生成」，而不会用样例数据或 0 填补。 详见仓库中的 web/README.md。
