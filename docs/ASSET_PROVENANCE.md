# Asset provenance

The Git repository contains this provenance record, expected checksums, and the
derived-asset builder. The deployed USD binaries remain in the controlled L20
runtime asset directory and are not duplicated in source control.

The first three source USD files in `/home/pc/CoRiBench/assets` were copied
from the self-contained factory assets already present on `franka2`:

- `factory_peg_8mm.usd` -> `peg_8mm.usd`
- `factory_hole_8mm.usd` -> `hole_8mm.usd`
- `franka_mimic.usd` -> `franka_mimic.usd`

The two additional contact-rich demos use six portable USDs extracted from the
FORGE deployment on `liaohe-l20`:

- `factory_gear_base.usd` -> `gear_base.usd`
- `factory_gear_medium.usd` -> `gear_medium.usd`
- `factory_gear_small.usd` -> `gear_small.usd`
- `factory_gear_large.usd` -> `gear_large.usd`
- `factory_nut_m16.usd` -> `nut_m16.usd`
- `factory_bolt_m16.usd` -> `bolt_m16.usd`

The source deployment is NVIDIA Isaac Lab 2.3.2 / Isaac Sim 5.1, pinned by the
FORGE container digest recorded in `/home/ubuntu/isaac-forge/VERSIONS.txt`.
`gear_base`, `gear_medium`, `nut_m16`, and `bolt_m16` are byte-identical copies
of the already flattened files under
`/home/ubuntu/isaac-forge/workspace/assets/factory`. The official FORGE
GearMesh configuration also requires the small and large flanking gears; those
two files were missing from the earlier portable export. They were retrieved
from the same Isaac 5.1 asset root and flattened with
`Usd.Stage.Flatten(addSourceFileComment=False)`. Their raw source hashes were
`c3284806005543e88006f10a2ee43454f4ceb4f43c72be810654c41afc46434c`
and `c0c494b877f3548cc1d74759e14f115c1ba548c53f5000e2337445a7eca01739`.

All nine borrowed USDs retain explicit provenance and their deployed hashes are
recorded in `assets/SHA256SUMS`. CoRiBench loads them only from its own asset
directory. The `gear_mesh` and `nut_thread` plugins use audited geometry
constants from the corresponding FORGE demos, but they do not import FORGE or
Factory environments, controllers, rewards, reset code, or success predicates.

`peg_8mm_convex.usd` is a CoRiBench-owned derived asset generated by
`assets/build_derived_assets.py`. It preserves the source rod geometry but
replaces the thin rod's SDF collision with a convex hull and sets a 0.25 mm
contact offset. This avoids unstable side contact and end-edge latching while
keeping the original `peg_8mm.usd` unchanged and auditable.

`assets/build_normalized_task_assets.py` generates the runtime wrappers under
`assets/normalized/` without modifying any source USD. Every single-body
wrapper is meter-scale, Z-up, has one root rigid body, no active joint, a root
origin on the support plane and `Support` / `Grasp` / `Mate` frames. Peg keeps
its convex hull; holes and gears keep SDF collision. The imported nut and bolt
collision meshes have open boundary loops and are therefore cooked with convex
decomposition instead of invalid non-watertight SDFs. The generated wrapper
hashes are recorded in `assets/SHA256SUMS`.

The default `contact_lab` visual profile does not reference external room or
table USD files. Its wall panels, lighting accents, bench frame and legs are
parameterized CoRiBench primitives. The visible tabletop is the same cuboid
that supplies the task collision surface, so both are exactly aligned at
`z=0`. This removes an otherwise unauditable height convention from visual
assets and allows the default scene to start without network downloads.

The `weight_sort` task uses NVIDIA's `flatbox_a02` visual through the normalized
`assets/normalized/weight_sort/box.usda` wrapper. Each episode spawns one box
whose mass is fixed to either `0.06 kg` or `0.18 kg`; the visual asset, scale,
material, friction and collision geometry are otherwise identical. Consecutive
seeds alternate the two masses so any complete 50-seed perfect dataset contains
25 light and 25 heavy episodes. Both sorting targets use `container_f27` at
scale `0.16` with matching task-owned collision shells. The light-box target
receives a black material override and the heavy-box target receives a blue
material override.

The `rattle_sort` task uses NVIDIA's `flatbox_a07` from
`SimReady_Containers_Shipping_01_NVD@10010.zip`, downloaded on L20 from the
official NVIDIA Omniverse downloadable asset-pack catalog. Only the complete
`flatbox_a07` source directory and its referenced MDL materials and textures are
deployed under `assets/simready/flatbox_a07/`. The original source measures
`0.25604 x 0.31720 x 0.11038 m`; `assets/build_rattle_sort_assets.py` applies a
uniform scale of `0.2109023311` to produce a graspable
`0.05400 x 0.06690 x 0.02328 m` parcel. Its generated wrapper uses six invisible
wall colliders so a separate `0.06 kg` insert can move and impact the shell.

Empty episodes assign the shell `0.18 kg`. Loaded episodes assign the shell
`0.12 kg` and place the `0.06 kg` loose insert inside it, preserving an exact
`0.18 kg` total mass in both classes. Consecutive seeds alternate empty and
loaded parcels, so every complete 50-episode perfect dataset contains 25 of
each. Both sorting targets use `container_f27` at scale `0.16`; the empty target
receives a black material override and the loaded target retains NVIDIA's native
blue material. The `parcel_sort_station` scene profile adds collision-free
industrial racks, a background conveyor, safety guards, and shelf parcels while
retaining the global robot base, tabletop support geometry, and main camera.

The `stove_turn_on` task uses the CC BY-NC 4.0 Lightwheel Kitchen
`Stovetop012` source asset at commit
`10b0f7a86135a27e8c2fba9c690f6bf5c4f06bb1`. The deployed source USD and
texture remain present with their exact runtime hashes recorded in
`assets/SHA256SUMS`.

`Stovetop012_single_center.usd` is a CoRiBench-authored, visual-only derivative
generated by `assets/build_single_stovetop.py`. The source combines the glass
slab and all five burner assemblies in one mesh, so the builder selects the
disconnected components inside a 0.145 m source-space half-width, retains only
the center control markings in the front knob bank, and replaces the shared
full-width slab with a 0.290 m wide charcoal-glass cuboid. It preserves the
source depth, height, center burner geometry, UVs, normals, and source material,
while reducing the body from 23,234 to 11,685 faces. The build is gated by the
exact source SHA-256 and is deterministic.

The environment wrapper loads that single-center derivative. A separate
fixed-base revolute articulation still reuses the unmodified source center-knob
geometry and receives the nonlinear detent effort at runtime; only its visual
material changes to brushed stainless steel so it remains legible against the
charcoal cooktop. Knob collision, mass, joint axis, limits, and friction are
unchanged. The emissive burner flame remains task-owned, collision-free visual
geometry.

The `faucet_turn` task uses the same Lightwheel Kitchen release's `Sink054`
asset through a visual-only wrapper that hides its original handle. A fixed
horizontal shaft extends the source faucet-side mount to a task-owned revolute
lever; the former freestanding cylindrical control is absent. The rotating
lever visually references the unmodified source `/root/Sink054_handle` mesh,
is yawed -90 degrees to align with the shaft plane, turns about the shaft's Y
axis in the vertical X-Z plane, and receives a
continuous nonlinear detent effort at runtime. Its simplified collision
geometry, water-stream visual, shaft, and articulation are task-owned.
The complete Lightwheel `KitchenRoom.usd` supplies the surrounding visual room
through a generated wrapper that removes all background physics, hides the
duplicate sink, source lights, and the camera-facing wall/window, then aligns
the room to the task-owned sink without moving the robot or main camera.
