# 任务说明索引

ForceBench 的八个任务共享同一套机器人 / 控制器 / 观测契约（详见
[基准标准化记录](../developer/benchmark_standardization.md)），但在**力信息是否真正
决定成败**这一点上分为截然不同的两类。**这个区分是本 benchmark 最重要的事实，
请不要跳过。**

## 第一类：力分类任务（5 个）

决定"什么才是正确行为"的物体属性**视觉上完全不可观测**，力是唯一携带该信息的通道。
这五个任务是 ForceBench 关于力感知的实际证据来源。

| 任务 | 中文名 | 策略必须靠力推断什么 | 物理量变化 | 专家数据 |
|---|---|---|---|---|
| [`weight_sort`](./weight_sort.md) | 按重量分拣箱子 | 箱子轻重（外观完全相同） | 质量 `0.06` / `0.18 kg` | 200 |
| [`rattle_sort`](./rattle_sort.md) | 按内部配重分拣包裹 | 包裹内部质量是否偏心（总质量恒为 `0.18 kg`） | 质心偏移 `±0.020 m`，约 `0.035 N·m` 力矩 | 200 |
| [`stove_turn_on`](./stove_turn_on.md) | 旋转灶台旋钮越过点火卡扣 | 旋钮是否已越过卡扣 | 非线性卡扣力矩，峰值 `0.12 N·m` | 200 |
| [`faucet_turn`](./faucet_turn.md) | 扳动龙头把手越过卡扣 | 同上，龙头把手 | 非线性卡扣力矩，峰值固定 `0.20 N·m` | 200 |
| [`radmanso_drawer_sort_table`](./radmanso_drawer_sort_table.md) | 拉开抽屉并在阻力上升处停手 | 抽屉阻力上升到何时该停手 | 起步阻力随机 `5.5–9.0 N` | 200 |

## 第二类：接触密集任务（3 个）

这三个任务的 `MANIFEST.description` 自称 "force-sensitive"，**但当前实现的成功判定
只检查最终位姿**（居中 / 就位 / 对齐 / 释放 / 退回），完全不读取力信号。
`peg_insert` 的 `spec.py` 里甚至没有任何力或质量常量。

**该措辞是前瞻性的（aspirational），当前实现下并不检验力感知。** 这三个任务是有用的
接触密集操作任务，但它们既不能证明也不能证伪"力感知是否有帮助"。在成功判定中加入
依赖力的检查是 v1.0 的待办项。

| 任务 | 中文名 | 实际变化的量 | 当前的力角色 | 专家数据 |
|---|---|---|---|---|
| [`peg_insert`](./peg_insert.md) | 销轴插孔 | 目标孔平面位置 | **无** —— `spec.py` 中没有任何力 / 质量常量 | **189**（不足 200） |
| [`gear_mesh`](./gear_mesh.md) | 齿轮啮合装配 | 底板位置、齿相位抖动 | 仅有 `mass_scale=8.0` 用于接触真实感，**不参与判分** | **62**（远不足 200） |
| [`nut_thread`](./nut_thread.md) | 螺母拧入螺栓 | 螺栓平面位置 | **不参与判分** | 200 |

## 关于判分逻辑的常见误读

五个力分类任务的判分依据是**环境内部的隐藏真值**（如 `box_kind`、旋钮卡扣角、
抽屉的设计阻力曲线）与最终位姿，**判分器本身不读取力传感器数值**。

这不是漏洞，而是刻意的设计：

- 策略**看不到**这些隐藏真值；
- 两个类别的**视觉外观完全一致**（甚至总质量都相同，如 `rattle_sort`）；
- 因此策略**只能**通过物理交互（力）来分辨。

判分器的职责是检查"分类 / 停手结果是否正确"，而不是检查"策略内部是否使用了力"。
后者在方法上不可能从外部黑盒验证——能验证的是"没有力信息就无法稳定超过随机水平"。
完整讨论见[评测协议](../eval_protocol.md#关于判分与力信号的关系)。

## 每份卡片包含什么

- 任务目标（中文翻译 + 模型实际收到的英文 prompt 原文）
- 场景描述
- 力相关性（如实标注属于上面哪一类）
- 物理量与随机化范围（以 `spec.py` 常量为准）
- 成功判定条件（以 `spec.py: evaluate_final_state` 和 `outcome.py` 的判据为准）
- 专家数据条数
- 依赖的第三方资产及其许可证（含未确认项）

**所有卡片均以代码为准。** 若卡片与 `forcebench/tasks/<name>/` 下的代码不一致，
以代码为准，并请提 issue。
